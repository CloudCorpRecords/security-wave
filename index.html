Greenlight checks if an agent may contribute. The Security Wave checks if what the agent touches is trying to rob it.

Four deterministic, offline tools, one job each: audit the persistence hooks hiding in a repo, pin the GitHub Actions that can be retargeted after review, scan the text an agent is about to read for injected instructions, and keep the receipts (history, diffs, and blame) when something changes. This board tracks their findings on our own factory in near real time, publishes the proof benchmarks, and keeps the program's problem ledger honest in public.

06 METHOD

Deterministic scanners, not vibes

Every tool is a static, offline analyzer with a fixed rule set. Same input, same verdict: the validation program runs each target three times and hashes the output. No model is consulted at scan time, so a result can be re-run and argued with.

Hand-verified before it is claimed

Findings are checked against source by a human-grade read before they enter the ledger: 2,785 actionpin findings verified line by line (100 percent accurate), 1,265 hookcheck findings presence-verified, every COMPROMISED verdict of the mega-corpus hand-read (30 of 30 were false alarms at the time, and the calibration fixes they forced are in the ledger).

Fixes before claims

The wave's standing rule: if a tool still has problems, it gets updates until it is solid, and only then does marketing get its numbers. Every number on this page traces to a data file generated from a named source: the npm registry, the GitHub API, the validation ledger, or the scheduled scan itself.

Freshness: this page updates itself

Nothing on this page is hand-exported. Every 15 minutes the pipeline re-reads npm, re-scans the watchlist, re-parses the committed ledger and program records in this repo, and re-runs a tool's full test suite from its release tag whenever the tool's version changes. Each section carries its own stamp: last scan for the feed and grid, the ledger file's last commit time for the counters, the tested version and time on each tool card, the pack date on proofs. The one human step left in the whole system: the validation process commits ledger and proof-pack updates as its work closes; everything downstream is automatic. The full loop is documented in SELF-UPDATE.md in this repo.
